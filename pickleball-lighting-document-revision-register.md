# Pickleball Lighting Document Revision Register

Prepared by AHFL Sports Lighting. This owner-side template tracks issued project documents. Adapt it to the contract and facility workflow. Assigned project parties determine technical requirements and approvals.

## Set up the register

Copy the table into the project record and create a row for each identifiable document. Record the document ID together with its revision and file location. Name the person who maintains the register. Ask the responsible issuer to resolve a mismatch before marking a reference current.

| Document ID | Court or asset | Record type | Current revision | Issuer | Review status | File location | Next action owner |
| --- | --- | --- | --- | --- | --- | --- | --- |
| [ID] | [Court / pole / fixture] | [Layout / schedule / instruction] | [Revision or issue date] | [Project party] | [Status] | [Owner storage path] | [Role] |

A suggested status legend distinguishes received, under review, current operating reference, superseded and missing. The assigned project party decides which status is appropriate. Receipt of a file leaves its review status open.

## Record a replacement reference

| Document ID | Previous revision | Replacement revision | Reason provided by issuer | Issued by and date | Register updated by and date |
| --- | --- | --- | --- | --- | --- |
| [ID] | [Revision] | [Revision] | [Recorded change] | [Role and date] | [Role and date] |

Retain earlier records according to the owner's retention and access rules. Use a clear current-reference field rather than silently replacing a file without recording the change. Keep credentials and private contact information in the owner's approved access process.

## Track missing information

| Missing reference | Requested from | Request date | Activity awaiting direction | Follow-up date | Response reference |
| --- | --- | --- | --- | --- | --- |
| [Document or specific field] | [Project party] | [Date] | [Task] | [Date] | [Reply or document ID] |

Use unknown when information has not been supplied. For example, an unconfirmed mounting position stays identified as an unresolved input until the responsible party provides the applicable record.

## Hypothetical example

A fictional facility receives Layout Revision B while an aiming note still cites Revision A. The register owner links both documents and marks the aiming reference under review. The assigned reviewer is asked which reference applies. If an updated note is issued, its ID, revision, issuer and date are logged. If the question remains open, it stays on the action list. This example describes document coordination and contains no measured AHFL project result or engineering approval.

## Check that the record can be used

Ask another facility team member to retrieve the current layout, an equipment schedule and the associated instruction through the register. Record broken locations or unclear revisions as follow-up items. When a proposed change affects the recorded input, keep the request and response with the affected documents.
